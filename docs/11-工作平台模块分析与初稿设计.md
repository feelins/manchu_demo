## 1. 一句话结论

**工作平台不是"第 7 个展示页面"，而是整个平台的生产侧**：前面六个模块是给访客看的（输入→出结果→走人），
工作平台是给我们自己人用的（标注、校对、纠错、沉淀训练数据）。它是**唯一需要登录**的部分，
也是唯一会**产出数据**（而不是只消费数据）的部分——OCR 标注的修正集、校对通过的语料、依存句法树，
最终都会回流成下一轮模型训练的数据。

一句话：**对外展示能力，对内生产数据。**

> **2026-09-25 追加：本文的"初稿"已经落成一个可点的演示版**（`/workbench/`，见 §7）。
> 它用 mock 数据把「登录 → 标注/校对 → 提交 → 审核 → 统计变化 → 权限拦截」整条流程演出来，
> **不落盘、不上传、不调模型**，专门用来讲清"工作平台是什么、怎么操作"。
> 真实平台要补的东西列在 §5 与 §7.3。

目录名里的"需登录，不对外"就是这个意思：不是"做得差不多的功能先藏起来"，
而是"这些工具本来就不是给公众用的"。

## 3. 初稿设计

### 3.1 权限模型（沿用 `docs/02` §3.6）

```
游客 < 注册用户 < 标注员 < 审核员 < 管理员
```

| 角色 | 工作台首页 | OCR 标注 | 双行校对 | 依存标注 | 审核 | 建号 |
|---|---|---|---|---|---|---|
| 游客 | ❌（导航置灰 🔒） | ❌ | ❌ | ❌ | ❌ | ❌ |
| 注册用户 | ✅ 只读 | ❌ | ❌ | ❌ | ❌ | ❌ |
| 标注员 | ✅ | ✅ 提交 | ✅ 提交 | ✅ 提交 | ❌ | ❌ |
| 审核员 | ✅ | ✅ + 验收 | ✅ + 验收 | ✅ + 验收 | ✅ | ❌ |
| 管理员 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

不依赖校内统一认证（`docs/02` 已定），**管理员手工建号**。

### 3.2 登录实现：选 Flask-Login（session），而非 JWT

`docs/02` §3.6 原写 "JWT + RBAC 自建"，初稿建议**先用 Flask-Login + session**，理由：

1. 三个工具都是**服务端渲染的页面**，不是前后端分离的 SPA，session 够用且更简单；
2. 无跨域、无多端（无小程序/App），JWT 的收益用不上；
3. `@login_required` 装饰器与蓝图天然契合，比手写 JWT 中间件少一大坨代码；
4. 将来真要前后端分离，换掉 `login_manager` 即可，接口层不用动。

账号存储：`data/users.json`（P0）→ SQLite（P1）。口令用 `werkzeug.security` 加盐哈希，**不明文**。
`data/` 目录不入库（进 `.gitignore`），避免账号进 git。

### 3.3 页面结构与路由

```
/workbench/                    工作台首页：我的任务 / 最近提交 / 三个工具入口   @login_required
├── /workbench/login           登录（唯一匿名可访问）
├── /workbench/logout
├── /workbench/ocr-annotate    满文古籍 OCR 标注（0701）        角色：标注员+
├── /workbench/proofread       满汉双行校对（0702）             角色：标注员+
├── /workbench/ud-annotator    依存句法标注（0703）             角色：标注员+
└── /workbench/review          审核台：待验收列表 + 通过/驳回     角色：审核员+
```

接口：

```
POST /api/workbench/annotations       上传标注结果（zip / json / conllu），带归属人
GET  /api/workbench/annotations       我的提交列表（分页）
GET  /api/workbench/annotations/<id>  取回某次提交（供复看 / 续标）
POST /api/workbench/annotations/<id>/review   通过 / 驳回 + 意见（审核员）
GET  /api/workbench/stats             我的统计：今日标注数、待改数、通过率
POST /api/workbench/detect            转发 7860 检测（可配置，缺省人工模式）
```

前端一律用**相对路径** `/api/...`，与 OCR / 翻译 / TTS 三个模块保持同一套网关约定（见 `docs/02` §3.2）。

### 3.5 三个工具怎么接入（逐项）

**0701 OCR 标注 —— 改动最大，价值也最大**

- 后端地址改配置：`INFERENCE_SERVER`（默认 7860）、`RECOGNITION_SERVER`（默认 1000）由门户注入，
  页面上可切换，存 localStorage（它本来就有这个能力）；**本机 OCR 在 8080**，故默认值要能覆盖。
- **检测服务 7860 本机没有**（在 Windows 工作站）。因此必须支持**「纯人工模式」**：
  服务不可达时禁用"AI画框 / AI预测"两个按钮并给出提示，人工框选 + 手工录入照常可用。
  否则本机演示时这工具等于打不开。
- CDN `jszip` → 下载到 `static/vendor/jszip.min.js`。
- 专用字体改用门户已有的 `static/fonts/001A-Buleku-R.ttf`（同一份文件，不必重复）。
- 导出产物**增加"上传到工作台"**：zip 落 `data/annotations/<user>/<时间戳>/`，同时保留本地下载。

**0702 双行校对 —— 先收编，择机重写**

- CDN `mammoth` → `static/vendor/mammoth.browser.min.js`（否则断网/内网直接不可用）。
- 性能问题按 `docs/02` 的办法：虚拟滚动 + Web Worker（大文件不卡主线程）。
- **初稿建议先原样收编**（它现在能用，只是慢），把重写放到 P1，避免阻塞 P0 上线。

**0703 依存标注 —— 改动最小**

- 纯前端，无后端依赖，直接挂进来即可（包一层门户外壳 + 页面标题）。
- File System Access API 保留为"高级选项"，**必须补降级路径**：不支持的浏览器走
  「下载文件 / 从本地选择文件上传到工作台」。
- localStorage 存的项目，增加"同步到服务端"按钮（否则清缓存即丢）。

### 3.6 数据落点（最关键的一个决策）

三个工具现在**都不落服务端**。两种走向：

| 方案 | 做法 | 优点 | 缺点 | 初稿建议 |
|---|---|---|---|---|
| **A 轻量（推荐先做）** | 工具保持本地导出，**另加一步"上传到工作台"**；服务端只存提交记录与文件 | 工具零改动、风险低、1 周内可见 | 不是实时保存，忘了上传就没记录 | **P0 走这个** |
| B 全托管 | 改工具存盘逻辑，每次标注自动存服务端、支持断点续标 | 体验好、可协同、可统计 | 三个工具都要改存储层，工作量大、易破坏现有逻辑 | P1 再评估 |

存储布局（方案 A）：

```
data/annotations/
├── <user_id>/
│   └── 2026-09-25T14-02-11_ja08027.zip
└── _index.json      # 提交记录：归属人、类型、文件名、时间、状态、审核意见
```

`data/` **不入库**（写进 `.gitignore`），与全量语料一样：代码进 git，数据不进。

### 3.7 统一外壳与依赖本地化

- 三个页面统一继承 `templates/base.html`，只把工具主体塞进 `{% block content %}`；
  各自的 CSS 保留（改动它们风险大），但收敛到 `static/css/workbench-*.css`，避免污染全站样式。
- 新建 `static/vendor/`，放 `jszip.min.js`、`mammoth.browser.min.js`，**彻底不依赖 CDN**。
- 导航"工作平台"：未登录时置灰 + 🔒（已实现，`config.py` 里 `locked: True`），
  登录后正常高亮。

## 5. 必须先确认的问题

1. **要不要 MVP 先行？** 即三个工具**原样嵌入**（不改一行代码、仍有 CDN、仍本机导出）只加一层登录。
   好处是 3~5 天出效果，坏处是"登录了但工具还是单机版"。**我倾向先做 MVP**——
   先把"需登录"这件事立住，工具的深度改造（尤其 0701）单独排期。
2. **账号怎么给？** 管理员手工建号（发账号密码）够不够？还是要做"申请 → 管理员审批"？
   涉及是否要邮箱/短信验证（会显著增加工作量）。
3. **7860 检测服务怎么办？** 它在本机不存在（Windows 工作站上）。三个选项：
   ① 接受"本机只能用人工模式"；② 把 `inference_server_local.py` + `manju_detect_v5.onnx` 迁到本机；
   ③ 云端部署后再联调。**这决定 0701 在本机能演示到什么程度。**
4. **标注数据的归属与用途**：标注结果（尤其修正集）谁拥有、能否直接用于下一轮训练、要不要留署名？
   这关系 `docs/10` 里的授权问题。
5. **0702 校对工具重写还是先用着？** 它慢但能用；重写要 1~2 周。

## 6. 风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 工具代码改动引入回归 | 三个 HTML 都是几百上千行的单文件，改后端地址/存储有破坏风险 | MVP 阶段**不改**，P0 改动前先备份原文件到 `docs/` 或 `legacy/`，逐项验证 |
| 检测服务缺失导致演示翻车 | 7860 本机没有，0701 的 AI 功能会报错 | 加人工降级模式；服务不可达时明确提示，而不是白屏 |

| 数据丢失 | 方案 A 下"忘了上传"就没有记录 | 工具页顶部常驻"上次提交时间"提醒；P1 考虑自动保存 |
| 浏览器兼容 | 0703 的 File System Access API 仅 Chromium | 补下载/上传降级路径 |
| 账号进 git | `data/users.json` 误提交 | `data/` 写进 `.gitignore`，并在提交前检查 |

## 7. 演示版（已实现，2026-09-25）

先回答那个问题：**能不能先用 mock 做纯演示？能，已经做好了。**

### 7.1 页面与能演什么

| 路由 | 演什么 |
|---|---|
| `/workbench/login` | 三种身份（标注员 / 审核员 / 管理员）直接选，卡片上写明各自权限 |
| `/workbench/` | 统计（提交数 / 待审核 / 已通过 / 通过率）+ 四个工具入口 + 最近提交列表 |
| `/workbench/ocr-annotate` | 6 张真实古籍图；「AI 画框」「AI 预测」模拟 1 秒返回 → 逐框核对 → 确认 → 提交 |
| `/workbench/proofread` | 12 句对，含 3 处人为错误（缺汉文行 / 多余空段落 / 汉满不对应）→ 上/下一处定位 → 修复 → 提交 |
| `/workbench/ud-annotator` | 3 句拉丁满文：分词 → SVG 依存树 → CoNLL-U 表 → 导出 → 提交 |
| `/workbench/review` | 审核台：通过 / 驳回（驳回须填意见），状态变化实时反映到首页统计 |
| 未登录访问 / 标注员访问审核台 | 分别演示"跳登录"与"403 拦截" |

### 7.2 刻意没做的事

- **不调任何模型**：AI 画框 / 预测 / 分词都是 `setTimeout` + 预置结果（真实检测服务 7860 本机没有）。
- **不落盘**：提交与审核记在**服务端内存**的列表里（各角色共享，重启门户即恢复初始）。
  之所以不存 session——标注员（A 浏览器）提交后，审核员（B 浏览器）看不到，
  "提交→审核"闭环就演示不出来。真实平台这里应换成数据库。
- **不做真鉴权**：登录页直接选身份，无口令校验、无口令存储。
- **导出只在浏览器本地生成**（CoNLL-U 用 Blob），不产生任何服务端文件。

### 7.3 从演示版走到真实平台，还差什么

| 缺什么 | 说明 |
|---|---|
| 真账号体系 | 口令（加盐哈希）或校内单点登录；注册/审批/停用；登录失败锁定 |
| 真 RBAC | 现在是装饰器比角色层级；真实场景要做数据级权限（只能看自己的任务） |
| 数据落库 | 提交记录、标注内容、审核意见入库；大文件走对象存储而非内存列表 |
| 并发与冲突 | 两人同时标同一页怎么办（锁 / 版本 / 任务分配） |
| 审计与备份 | 谁在什么时候改了什么；定期备份与恢复演练 |
| 数据合规 | 标注数据的授权、署名、能否用于训练（与 `docs/10` 第 5 节同源问题） |
| 传输安全 | 演示版是 HTTP + 明文 cookie；上线必须 HTTPS（`Secure` cookie） |
| 多实例 | 现在内存列表只在单进程内共享；多 worker 部署必须换成共享存储 |

> 结论：演示版验证的是**流程与交互**，不是**工程实现**。
> 从它到能上线的工作平台，主要工作量在上面这张表，尤其"数据落库 + 并发 + 权限"三块。
