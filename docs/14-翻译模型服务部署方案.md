## 3. P0：起 600M 双向模型（不依赖 GPU、不占新磁盘）

### 步骤

1. **备份原脚本**
   ```bash
   cd ~/translation_experiments
   cp api_server_v2.py api_server_v2.py.bak
   ```

2. **改默认端口 8000 → 8001**（8000 已被门户占用，必须改）

   同时把模型路径、端口改成环境变量可覆盖，便于后续切换 v3.0。

3. **起服务**（CPU 推理；内存 125G、32 核足够）
   ```bash
   nohup python api_server_v2.py > ~/translation_experiments/api_8001.log 2>&1 &
   ```

4. **验证**
   ```bash
   curl http://127.0.0.1:8001/health
   curl -X POST http://127.0.0.1:8001/translate \
        -H 'Content-Type: application/json' \
        -d '{"text":"bi sain","direction":"mnc2zho"}'
   ```

5. **门户侧验证**
   ```bash
   curl http://127.0.0.1:8000/api/translate/health   # 8001 应 alive
   ```
   再打开 `/translate/` 页面实际翻一句。

6. **常驻**：验证通过后按 P0 收尾做成 systemd 托管（与门户、OCR、TTS 一致）。

### 环境选择

| 环境 | torch | transformers | fastapi/uvicorn | 评价 |
|---|---|---|---|---|
| `trans` | 2.9.1+cu126 | 4.57.3 | ❌ 缺 | **版本与训练时最接近**，需补装 fastapi/uvicorn |
| `base` | 2.11+cu130 | 5.5.0 | ✅ 有 | 依赖齐，但 transformers 偏新 |

**策略**：先用 `base` 做加载冒烟（快）；若 transformers 5.x 与 M2M100 有兼容问题，
改用 `trans` 并补装 fastapi/uvicorn（约几十 MB，磁盘可接受）。

### 风险

- `cuda.is_available()` 为 False（驱动挂），会走 CPU；600M 模型 CPU 推理秒级，可接受
- v1.0 质量标注为"基本可懂，需人工校对"，演示时措辞上要如实说明

## 4. P1：修 NVIDIA 驱动 → 起 7B/14B LoRA

### 步骤

1. 诊断驱动
   ```bash
   nvidia-smi                        # 当前失败
   lspci | grep -i nvidia            # 硬件在：2×RTX 3090
   dkms status; ls /usr/src | grep nvidia
   uname -r                          # 内核版本（驱动是否匹配）
   ```
2. 常见原因：内核升级后 DKMS 未重编、Secure Boot 拦截、驱动版本不匹配
3. 修好后 `torch.cuda.is_available()` → True，用 `trans` 环境起 7B LoRA
   （`Qwen2.5-7B` 15G 权重 + `qwen2.5_7b_lora_opt` 323M 适配器都在本机）
4. 单卡 24G 放 7B（bf16 约 15G + 适配器）没问题，多卡可上 14B

### 收益

翻译质量比 600M 高一档，且 GPU 推理更快。

### 只读诊断结果（2026-09-30）

| 项 | 结果 |
|---|---|
| 内核 | `7.0.0-30-generic` |
| 显卡 | **2×RTX 3090**（24G×2，包含音频设备共 4 条 PCI 记录） |
| nvidia 内核模块 | **0 个已加载** |
| 驱动源码 | `/usr/src/nvidia-580.173.02`、`nvidia-srv-580.173.02` **在** |
| Secure Boot | **已禁用**（不是它拦的） |
| nouveau | 未加载（未抢占） |

**结论**：驱动源码包在，但**未针对当前内核编译/加载**——典型的内核升级后 DKMS 没重编。

**修复命令（需 sudo，由管理员执行）**：

```bash
# 方式一：让 DKMS 针对当前内核重编（推荐，保留现有驱动包）
sudo dkms install nvidia/580.173.02 -k $(uname -r)
sudo modprobe nvidia
nvidia-smi          # 验证

# 方式二：重装驱动包（更彻底，耗时更长）
sudo apt install --reinstall nvidia-driver-580
sudo reboot
```

> 本门户账号无免密 sudo，上述命令需在管理员终端执行。执行后
> `python -c "import torch;print(torch.cuda.is_available())"` 应输出 `True`。

## 5. P2：清磁盘 → 转 27B GGUF → 8005

### 步骤

1. **清磁盘**（当前仅剩 1.6G，必须先清）
   可清理的中间产物（**清理前确认不再需要**）：
   ```bash
   du -sh ~/translation_experiments/exp_*    # exp_C_600M_v3.0 26G、exp_C_600M_bidirectional 25G …
   ```
   > 注意：`exp_*/final/` 是要保留的成品，只清 `checkpoint-*` 中间目录

2. **确认 27B GGUF**
   当前 `~/qwen3.6_27b_q4_K_M.gguf` **是个目录**（内含 17.9G safetensors），不是 GGUF 文件；
   真正的 Q4_K_M GGUF 可能只在 Windows D 盘。本机 52G 原始权重可用 llama.cpp 转换。

3. **起 8005**
   ```bash
   ~/llama.cpp/llama-server -m <27B.gguf> --port 8005 --host 127.0.0.1
   ```
   门户 8005 走 OpenAI 兼容协议，`llama-server` 原生支持，无需改代码。
