## 3. 本机服务调研（结论：不接入后端）

用户要求「在本机查找合适的服务」，调研过程与结论如下。

### 3.1 检索范围

```bash
find /home/leyesi -maxdepth 3 -iname "*translit*" -o -iname "*roman*" -o -iname "*latin*"
grep -rl "转写\|互转\|romanis\|translite" /home/leyesi --include="*.py"
ss -lntp          # 当前监听端口
```

**监听端口现状**：22 / 8000（门户）/ 8080（OCR）/ 3389 及若干本地回环端口，**没有任何转换类服务**。

### 3.2 候选评估

| 候选 | 位置 | 能否承担本模块 | 结论 |
|---|---|---|---|
| TTS 文本转换 | `/home/leyesi/shaopf/manchu_TTS/app.py` → `POST /api/convert` | 功能是 `text_normalize()` + `g2p()` → 输出 `latin_text` 与 **cmudict 音素**，为 TTS 合成服务 | ❌ 单向、面向发音，**不是双向互转**，且无 `-i`/`ci` 等满文正字规则 |
| MFA 拉丁音素脚本 | `shaopf/scripts/prepare_data_mfa_latin*.py` | 语音对齐的数据预处理脚本 | ❌ 离线脚本，非服务 |
| 前端规则引擎（源页面自带） | 页面内联 | 完整双向规则 + docx 支持 | ✅ **采用** |

### 3.3 决策

保留纯前端实现，理由：

1. **规则完备**：已是成品，服务端重写等于把 614 行规则重新实现一遍，无收益
2. **零部署成本**：无需新增端口、无需常驻进程、不受 GPU/驱动影响
3. **隐私与性能**：文档内容不必上传到服务器，转换在本地毫秒级完成
4. **离线可用**：docx 解析/生成自实现，无库依赖，可整体打包分发

**代价**：规则更新需前端发版；若未来要提供 OpenAPI 供第三方调用，可将规则表搬到服务端，
在 `modules/translit/__init__.py` 内新增 `/api/translit/convert` 即可，前端规则表可复用。

## 4. 移植方案

### 4.1 分工原则

| 产出 | 做法 | 理由 |
|---|---|---|
| `static/js/translit.js` | **sed 原样提取**（484–1097 行） | 逻辑复杂（zip/docx），手抄必错；零改动最稳 |
| `templates/translit/index.html` | 继承 `base.html`，重写布局 | 接入门户统一外壳（导航/页脚） |
| `static/css/translit.css` | **完全重制** | 源配色与门户风格不一致，需视觉统一 |
| `modules/translit/__init__.py` | 仅页面路由 | 无后端依赖 |

### 4.2 保证 JS 零改动的两个前提

移植前先提取了 JS 的全部 DOM 依赖，写模板时逐一满足：

```
getElementById: batchActions fileList input input-stats label-input label-output
                output output-stats processBtn progressBar progressFill toast txtBtn wordBtn
querySelectorAll('.mode-btn')     ← 类名必须保留
classList: active / show
```

→ 因此模板**保留源 HTML 原有类名**（`mode-btn`、`file-btn`、`batch-btn`、`vertical-mode`…），
只在 CSS 层重定义外观。去掉的只有 `container` / `header-sidebar`（门户已有统一 header 与竖排标题空间）。

### 4.3 文件清单

| 文件 | 说明 |
|---|---|
| `templates/translit/index.html` | 页面模板（继承 `base.html`） |
| `static/css/translit.css` | 模块样式（令牌化） |

`config.py` 无需修改——`NAV_ITEMS` 与 `CAPABILITY_CARDS` 早已预留 `translit` 条目，
本次只是把占位路由换成真实蓝图，导航「文字转换」自动生效。

### 6.1 配套样例集

`docs/samples/translit/` 提供可直接使用的样例与回归基准，
满文原文取自 OCR 真实输出，拉丁结果用同源规则生成（详见该目录 README）：

```
manju/    → latin/      满文→拉丁 的输入/预期输出
latin/    → reverse/    拉丁→满文 的输入/预期输出
expected/04-cheatsheet.tsv   规则对照表（由规则表自动推导）
```

生成与回归：`scripts/gen_translit_samples.py`（脚本内嵌与 `translit.js` 完全一致的规则表，改规则需同步并重跑）。

**发现并记录的两个规则有损点**（源规则表固有，非移植缺陷）：

| 现象 | 实例 |
|---|---|
| 裸 `c` 不可逆 | `ᡮ`(U+186E) → `c`，反向表无裸 `c` 条目 |
| 元音序列失真 | `ᠣᡠ` → `ou` → 还原成 `ᠣᠣ`（后置修正 `ou→oo` 单向） |

因此两个方向的预期输出分开保存，不做严格互逆假设。
