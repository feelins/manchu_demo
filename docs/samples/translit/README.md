# 文字转换（传统满文 ⇄ 拉丁满文）样例集

配套模块：`/translit/`。这里的样例用于**功能验证、回归测试与演示**，
满文原文取自本机 OCR 的真实识别输出（非人工编造），拉丁结果用**与浏览器完全一致的规则**生成。

---

## 1. 目录结构

```
translit/
├── manju/                  传统满文原文（「满文 → 拉丁」模式的输入）
│   ├── 01-single.txt       单段（一行一段，最常用）
│   ├── 02-page.txt         整页多列（每行一列，演示段落结构保留）
│   ├── 03-mixed.txt        多来源混合（演示批量 / 文件夹模式）
│   └── 04-cheatsheet.txt   规则速查（逐条列出特殊拼写）
├── latin/                  拉丁满文（「满文 → 拉丁」的 **预期输出**）
│   └── 01-single.txt ...
├── reverse/                「拉丁 → 满文」的 **预期输出**
│   └── 01-single.manju.txt ...
├── expected/
│   └── 04-cheatsheet.tsv   满文 ↔ 拉丁对照表（含字符映射 / 拼写修正两类注释）
└── README.md
```

**配对关系**（每个方向都有输入 + 预期输出）：

| 方向 | 输入 | 预期输出 | 是否严格互逆 |
|---|---|---|---|
| 满文 → 拉丁 | `manju/*.txt` | `latin/*.txt` | ✅ 一致 |
| 拉丁 → 满文 | `latin/*.txt` | `reverse/*.manju.txt` | ✅ 一致 |

> ⚠️ **两个方向共用 `latin/`**：`latin/` 既是正向输出，也是反向输入。
> 但 `reverse/` 的结果 **不等于** `manju/` 原文 —— 规则并非严格互逆，详见第 4 节。

## 2. 用法

### 2.1 页面手测（最快）

打开 `http://127.0.0.1:8000/translit/`：

| 想验证 | 模式 | 操作 |
|---|---|---|
| 满文 → 拉丁 | `满文 → 拉丁` | 粘贴 `manju/01-single.txt` 内容 → 执行转换，应与 `latin/01-single.txt` 一致 |
| 拉丁 → 满文 | `拉丁 → 满文` | 粘贴 `latin/01-single.txt` 内容 → 执行转换，应与 `reverse/01-single.manju.txt` 一致 |
| 批量 | 任一 | 上传 `manju/` 内多个文件 → 开始批量转换 → 导出 TXT / Word |
| Word 段落保留 | 任一 | 上传 docx，确认段落未被合并 |

### 2.2 命令行回归（可自动化）

```bash
cd /home/leyesi/shaopf/manchu_demo
.venv/bin/python scripts/gen_translit_samples.py
```

脚本会重新生成全部样例，并打印回归校验：

```
01-single        正向(满→拉)预期一致: True   反向(拉→满)预期一致: True   严格互逆: True
02-page          正向(满→拉)预期一致: True   反向(拉→满)预期一致: True   严格互逆: False

```

> 规则表在 `scripts/gen_translit_samples.py` 里**照抄** `static/js/translit.js`
> （连替换顺序都一致）。改了一端就必须同步另一端，然后重跑此脚本确认未引入偏差。

## 4. 已知的有损点（重要）

这是**源规则表本身的特性**，不是移植引入的缺陷。转换并非数学意义上的双射，以下情况会失真：

| # | 现象 | 实例 | 原因 |
|---|---|---|---|
| 1 | 裸 `c` 无法还原 | `ᡮ`(U+186E) → `c` → 回不到 `ᡮ`，仍为拉丁 `c` | 正向规则有 `0x186E → c`；反向表只有 `c'` 与 `ci`，没有裸 `c` 的条目 |
| 2 | 元音序列失真 | `ᠣᡠ` → `ou` → 还原为 `ᠣᠣ` | 后置拼写修正 `ou → oo`（同理 `uu → uo`、`iu → io` 等）在反向是单向的 |
| 3 | 独立元音附加形式 | `" i "` → ZWJ+`i`（U+200D+U+1873） | 反向规则里这一条针对独立出现的 i，与词内 i 拼法不同 |

**影响**：`latin/`、`reverse/` 是可靠的回归基准；
但不要假设 `latin/xx.txt` 转回满文一定等于 `manju/xx.txt`。

**规避建议**：若需要严格往返（语料校对场景），优先走「拉丁 → 满文」方向，
并避免源文中出现裸 `c` 与 `ou/uu/iu` 等组合；或在服务端改用带分词的完整正字引擎。
