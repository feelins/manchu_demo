- 演进：模板层保持"外壳 + 内容块"结构，将来换 Vue 只是替换渲染层，后端 API 契约不变。

## 3. 核心设计

### 3.1 统一外壳与设计系统（P1）

- `templates/base.html`：机构条（通化师范学院 · 吉林省高校哲学社会科学实验室 · 长白山非物质文化遗产数智化保护与传承实验室）+ 品牌 + 导航 + `{% block content %}` + 页脚（合作单位 / 备案 / 版权）。
- 设计令牌抽到 `static/css/design-token.css`：`--gold:#c9a227`、`--green:#2e7d5a`、`--cream:#faf8f5`、`--ink:#0f1626` 等，所有模块复用。
- 导航**当前项高亮**（`is-active`）、工作平台未登录**置灰并加 🔒**。
- 字体：`001A-Buleku-R.ttf` → **WOFF2 + 子集化**（`fonttools`），竖排沿用 `writing-mode: vertical-lr; text-orientation: sideways-right`。
- 第三方库本地化：`jszip`、`mammoth` 下载到 `static/vendor/`，**不依赖任何 CDN**。

### 3.2 后端地址配置化（C3 的关键）

`.env` 示例：

```ini

```

前端**只允许**出现 `/api/xxx` 相对路径，由门户蓝图转发到上述地址。

### 3.3 满文⇄拉丁规则引擎（单一实现）

互转规则现在散落在 02 页面（内嵌 `MANJU_TO_LATIN_RULES` / `LATIN_TO_MANJU_RULES`）与 TTS 页面（自己写了一版拉丁→满文），ASR 还需要同一份规则。
**必须抽成 `common/manju_rules.py` 一个实现**，对外提供：

```python
manju_to_latin(text, scheme="molendroff") -> str
latin_to_manju(text, scheme="molendroff") -> str
```

前端需要的场景（TTS/ASR 实时同步显示）通过 `/api/translit` 调用同一实现，避免两套规则不一致。

### 3.4 推理过程可视化（统一 Trace 面板）

**统一数据结构**（后端返回或 SSE 推送，`common/trace.py` 定义）：

```json
{
  "trace_id": "trace_20260924_xxx",
  "task": "translate | tts | asr | ocr",
  "status": "running | done | failed | fallback",
  "steps": [
    {"index":0,"key":"segment","title":"分词与形态分析","status":"done",
     "duration_ms":128,"summary":"...","payload":{...},
     "view":"token-list|table|barchart|spectrogram|waveform|text-diff|heatmap"}
  ],
  "final": {"text":"...","audio_url":"...","score":0.78},
  "meta": {"model":"...","device":"cpu","is_demo":false}
}
```

| 任务 | 步骤链（`steps.key`） |
|---|---|
| `translate` | `normalize → segment → morphology → syntax → retrieve → llm-stream → postprocess → score` |
| `tts` | `normalize → latinize → phonemize → prosody → acoustic(mel) → vocoder → waveform` |
| `asr` | `load → vad → feature → acoustic-frame-posterior → ctc-decode → latin-text → manju-script` |
| `ocr` | `load → layout → box-detect → column-split → char-recognize(conf) → manju-text → (optional)latin` |

技术要点：
- 长耗时任务用 **SSE**（`text/event-stream`）推送步骤事件；Flask 直接 `Response(generator, mimetype='text/event-stream')` 即可；
- 每步必带 `duration_ms`，渲染成"耗时条"；
- 失败/降级置 `status=fallback` 并高亮提示；
- 频谱 / 热力图 / 波形等中间产物**由后端生成 PNG 或 JSON**，前端不重算。

### 3.5 演示保障（本期优先级最高的工作）

| 层级 | 做法 | 覆盖 |
|---|---|---|
| 第一层 | **预生成缓存**：上线前把会被点到的示例跑一遍，存 `static/demo/` + Redis，命中即秒回 | 约 90% 操作 |
| 第二层 | **SSE 进度反馈**：真跑的请求流式回步骤事件 | 剩余 10% 不显卡死 |
| 第三层 | **演示模式开关**：`DEMO_MODE=on` 或 URL `?demo=1`，强制走预置结果 | 断网/模型挂掉不开天窗 |

预生成内容清单：

| 模块 | 内容 | 数量 |
|---|---|---|
| 互转 | 无需（纯规则，毫秒级） | — |
| OCR | 经典古籍图 + 识别结果 | 3~5 组 |
| 翻译 | 经典句对（可取自 `06语料集/.../all1+2+3.txt`） | 10~20 组 |
| TTS | 示例文本 + 音频 + 频谱图 | 3~5 组 |
| ASR | 示例音频 + 识别结果 | 2~3 组 |
| 语料集 | 每类语料样例 | 各 20~50 条 |

> 这些内容在**工作站上用真模型跑一遍导出**，随镜像/代码一起部署到云端 —— 这就是"工作站干活、云端演示"的落地方式。

### 3.6 权限与账号（阶段 5）

`游客 < 注册用户 < 标注员 < 审核员 < 管理员`；**JWT + RBAC 自建**（不依赖校内认证）。
工作平台三个页面加 `@login_required` + 角色校验；未登录时导航入口置灰。

### 3.7 部署形态

沿用总体方案：**Docker Compose + 配置外置 + 数据与代码分离**，工作站与云端共用同一份 `docker-compose.yml`，差异全部收敛到 `.env`。
云端**纯 CPU 服务器**：轻量 4核8G（约 1,100~1,600 元/年）或 ECS 经济型 e 8核16G 包年（≈4,150 元/年）；**本期不买 GPU**。
上线硬前置：**域名 + ICP 备案（10~20 工作日）**，第 1 周启动。

| **阶段 5 工作平台（轻量版）** | 能登录、能看界面、能讲流程 | JWT + RBAC；三个页面收编 + 风格统一；校对工具重写（虚拟滚动 + Web Worker） | 登录受控的工作台 | 3~4 周 |
| **阶段 6 上云** | 对外可访问 | Docker Compose；`.env` 切换；OSS/COS；域名 + 备案 + HTTPS；预生成内容部署 | 公网可访问站点 | 2~3 周（备案并行） |

> **验收最短路径：阶段 0 → 1 → 2 → 3。** 阶段 3 优先级高于阶段 4 —— "点不动"比"没有酷炫面板"致命得多。

## 6. 风险

| # | 风险 | 应对 |
|---|---|---|
| R0 | **现场真推理太慢、页面像卡死**（头号风险） | 阶段 3：预生成缓存 + SSE 进度 + 演示模式开关；动线先走缓存 |
| R1 | 大模型翻译现场翻车（CPU 几十秒~几分钟） | 默认不触发；必要时提前 5 分钟预热或临时按量租 A10 |
| R3 | 备案耗时长导致开不了站 | 第 1 周提交；备案期间用 IP + 端口内部验收 |
| R5 | CDN 依赖导致加载失败 | jszip / mammoth 全部本地化 |
| R7 | CPU 内存不足 OOM | 16G 规格；容器内存限制 + 自动重启；大模型不上云 |
| R9 | 校对工具"巨慢" | 直接重写：虚拟滚动 + Web Worker + 增量渲染 |
| R10 | 满文编码/字形错乱 | 统一 UTF-8；字体子集化固定；零宽字符显式处理 + 测试用例 |
| R12 | 模型/镜像体积过大 | 模型与镜像分离，走对象存储分发 |
