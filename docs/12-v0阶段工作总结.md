## 3. 门户基建（阶段 0~1）

- **骨架**：Flask 单应用 + 蓝图分模块（`modules/<模块>/`），`app.py` 统一注册；`/health` 健康检查。
- **统一外壳**：`base.html` + `design-token.css` / `base.css`；导航与页脚**数据化**到 `config.py`
  （`NAV_ITEMS` / `FOOTER_LINKS`），8 个导航项全部有真实路由（语音识别指向占位页）。
- **首页**：能力卡片、语料数据卡、`TRACE_PIPELINES` 推理链路三栏全部由 `config.py` 驱动，模板不堆砌 HTML。
- **服务编排**：`scripts/services.sh`（三服务统一启停、按监听端口反查 PID，修正过状态误报）。

## 4. 各模块要点

**① 古籍 OCR（✅）**——从原 HTML 静态页收编为动态蓝图，保留竖版批量与汉字识别开关；
后端 8080 实测可用，`/api/ocr/health` 200。踩坑与降级根因见 [06](./06-OCR服务现状与联调记录.md)。

**② 文字转换（✅）**——纯前端规则引擎，满文 ⇄ 拉丁互转，支持整篇处理；
`scripts/gen_translit_samples.py` 生成样例集与回归基准（`docs/samples/translit/`）。

**③ 满汉双向翻译（⚠️ 缺服务）**——页面与代理层已收编，**三个模型的协议差异在代理层抹平**
（Qwen / GPT-OSS / GLM 三种请求响应格式统一），但三个模型服务运行在 Windows 工作站，
本机 8001/8003/8005 全部无响应，**当前点击无法出结果**。这是 v0 演示的最大风险点。

**④ 语音合成（✅）**——音频回源代理（引擎产物由门户回源转发，避免路径暴露）；
`c74953b` 起支持传统满文输入，送引擎前自动转写为拉丁。7868 服务在跑。

**⑤ 语音识别（❌）**——`/asr/` 为 Coming Soon 占位页；`05语音识别/` 规划目录本身为空（0 文件），
属"从零开发"项，不算规划遗漏。

**⑥ 语料集（✅ 样例浏览）**——四页面：
`/corpus/` 总览（5 类卡片 + 口径标注）、`/corpus/parallel`（30 句对，汉文/拉丁满文/反写满文 + 过滤）、
`/corpus/ocr`（真实古籍 / 合成双页签）、`/corpus/speech`（6 条音频 + 文本）。
**只展示切片**（816 KB），全量数据留在原路径不入库；`scripts/make_corpus_samples.py` 等距抽样，重跑可复现。
**导出 / 申请通道尚未做**。

**⑦ 工作平台（⚠️ mock）**——`/workbench/` 需登录，三个演示角色**免密**（张同学-标注员 / 李老师-审核员 / 王老师-管理员），
覆盖 OCR 标注、句对对齐、审核统计全流程；数据存在 Flask session 里，**不落盘、换浏览器即空**。
底稿用真素材（语料切片里的古籍图与句对），标注状态是假的。

## 5. 首页 / 语料页数字口径（对账一致）

首页 5 张数据卡、`/corpus/` 总览、`/api/corpus/stats` **三处核对一致**，无漂移：

| 卡片 | 数字 | 实测口径 |
|---|---|---|
| 满文 OCR 训练数据 | 190,368 张 | 合成 173,170 + 真实古籍 17,198（需求文档写 1,430,707 / 8,599，口径不同） |
| 满汉平行语料 | 49,019 句对 | 98,038 行双行对照 |
| 语音合成数据 | 2,424 条 | `Manchu_data_v8`（wav + 音素对齐） |
| 语音识别数据 | 2,424 条 | 与合成**共用同一批 wav，不重复计入总量** |
| 已有古籍总量 | 17,198 页 | 古籍扫描图（102 MB）；「种/套」数本机无清单 |

**改数字的两个入口（两处都要改，否则首页与总览页不一致）**：

- `config.py` → `CORPUS_STATS`（首页数据卡）
- `modules/corpus/__init__.py` → `CORPUS_OVERVIEW`（`/corpus/` 总览卡片，含 `scale` / `verified` / `note`）
