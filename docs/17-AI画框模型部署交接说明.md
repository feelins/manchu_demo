## 1. 这是什么

满文古籍**单词框检测**模型（YOLOv8n，单类），输入整页古籍扫描图，输出每个单词/文本块的边框坐标。已数据飞轮迭代至 v6，部署形态为 **Ubuntu 常驻 HTTP 推理服务**。

| 项 | 值 |
|---|---|
| 模型文件 | `/home/leyesi/manju_detect/manju_detect_v6.onnx`（约 12.5MB） |
| 服务脚本 | `/home/leyesi/manju_detect/inference_server_local.py`（FastAPI + onnxruntime） |
| Python 环境 | `/home/leyesi/manju_detect/.venv/` |
| 监听地址 | `0.0.0.0:7860` |
| systemd 服务 | `manju-detect.service`（用户级，开机自启 + 崩溃自愈） |
| 实测性能 | CPU 推理约 **68ms/页**（CUDA 后端未启用，见 §6） |

⚠️ **不要混淆**：本服务是 YOLO 单词框检测。另有一个 **Mask R-CNN 版面分析服务**（版框/列/小注区）在 `~/ocr_deploy/`（端口 8080），那是另一条任务线，与本次交接无关。

## 2. API 契约（前端只需知道这个）

### `POST /detect`

- 请求：`multipart/form-data`，字段名 **`file`**，内容为整页图片
- 响应 JSON：

```json
{
  "image_width": 1654,
  "image_height": 2339,
  "boxes": [
    {"x": 224, "y": 542, "w": 140, "h": 619, "confidence": 0.7353}
  ],
  "box_count": 19,
  "inference_time_ms": 67.68
}
```

- `boxes` 为**原图像素坐标**（左上角 x,y + 宽高），已按 (x, y) 升序粗排；前端的列优先编号逻辑自行处理，不受此影响
- 模型未加载时返回 HTTP 503

### 辅助接口

| 接口 | 说明 |
|---|---|
| `GET /health` | 健康检查，返回 `model_loaded`、`model_path`、`providers` |
| `GET /` | 服务信息 |

### 推理参数（脚本内常量，如需调整改脚本后重启服务）

- 输入：letterbox 至 640×640（灰边 114 填充，居中）
- 置信度阈值 `CONF_THRESHOLD = 0.25`
- NMS `IOU_THRESHOLD = 0.45`

## 3. 前端接入方式

前端是浏览器本地打开的标注工具 HTML（v8.x），通过 **SSH 隧道**访问本服务（校园网 aTrust 白名单仅放行 22/23/3389/5900，8000/7860 均无法直连，必须走隧道）。

### 步骤

1. **确认/修改 HTML 中的服务地址**（搜 `INFERENCE_SERVER`）：

   ```js
   const INFERENCE_SERVER = "http://localhost:7860";
   ```

2. **PC 建立隧道**（批处理已更新，双击即可，需先连 aTrust）：

   ```bat
   C:\Windows\System32\OpenSSH\ssh.exe -L 8000:127.0.0.1:8000 -L 7860:127.0.0.1:7860 leyesi@10.22.0.17
   ```

   - `8000` → manchu-portal 门户
   - `7860` → 本 AI 画框服务

3. 前端 `aiDetect()` 按既有逻辑 `POST ${INFERENCE_SERVER}/detect` 即可，返回格式与旧 Windows 本地服务**完全一致**，无需改动解析代码。

### ⚠️ 废弃事项

- PC 上的旧本地推理服务（`D:\满文训练\scripts\inference_server_local.py` 手动起的那个）**不要再启动**——它会抢占本地 7860 端口，导致隧道绑定失败。
- 模型更新只动 Ubuntu：替换 onnx 文件 → `systemctl --user restart manju-detect` → 完成。PC 侧无需任何操作。

## 4. 服务运维（Ubuntu 上）

```bash
systemctl --user status manju-detect      # 状态
systemctl --user restart manju-detect     # 重启（换模型/改阈值后）
journalctl --user -u manju-detect -f      # 实时日志
curl -s http://127.0.0.1:7860/health      # 健康检查
```

unit 文件：`~/.config/systemd/user/manju-detect.service`
