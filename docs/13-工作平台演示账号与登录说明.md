## 2. 登录入口

| 入口 | 说明 |
|---|---|
| 首页「工作平台」区块整句 | 「仅对平台内部人员开放 · 需登录并获得相应权限 →」可点击 |
| 首页「进入工作台（需登录）→」按钮 | 工作平台三张卡片下方的金色按钮 |
| 顶部导航「工作平台」 | 带锁标，点击同样先到登录页 |
| 直接访问 `http://<IP>:8000/workbench/login` | 未登录访问 `/workbench/任意页` 会被 302 到这里，并带 `?next=` 回跳参数 |

登录后跳回 `next` 指定的页面，没有则进工作台首页。退出：`/workbench/logout`。

## 3. 权限是怎么拦的

实现都在 `modules/workbench/__init__.py`：

| 机制 | 位置 | 行为 |
|---|---|---|
| `_login_required` | 装饰在每个业务视图上 | 未登录 → 302 到登录页（带 `next`） |
| `_role_required(role)` | 装饰在审核台等视图上 | 角色层级不足 → 渲染 `denied.html`，**HTTP 403** |
| `current_user()` | 读 `session["wb_user"]` | 页面顶部显示当前身份 |

**注意**：口令不写入 session——登录成功后只把展示需要的字段放进会话，见 `login()`。

## 4. 演示脚本（建议照这个顺序讲）

1. 首页点「进入工作台（需登录）→」→ 登录页
2. 用 **标注员 `zhang`** 登录 → 进入工作台，注意顶部身份与统计
3. 打开「满文古籍 OCR 数据标注」→ 提交 → 工作台统计里「待审核 +1」
4. 直接访问 `/workbench/review` → **被挡在门外（403）**，讲一句"这就是 RBAC"
5. 退出，用 **审核员 `li`** 登录 → 审核台能看到刚才那条提交 → 通过/驳回 → 统计变化
6. 用 **管理员 `wang`** 登录 → 权限全开，可演示数据重置（`/workbench/reset`）

> 提交记录存在**模块级共享列表**（不是各自 session），所以 A 浏览器提交、B 浏览器能看到，
> 这个闭环才演得出来。代价是所有访客共享一份演示数据。

## 6. 与真实平台的差距（务必在汇报时说明）

这一版刻意不做的事，真实平台必须补（详见 [11](./11-工作平台模块分析与初稿设计.md) 第 5 节）：

| 项 | 演示版 | 真实平台 |
|---|---|---|
| 口令 | 明文写在 mock 数据里，字符串比对 | 加盐哈希存库（bcrypt/argon2） |
| 账号体系 | 3 个预置账号 | 账号管理 + 校内单点登录（CAS/OAuth） |
| 登录保护 | 无 | 失败次数锁定、验证码、审计日志 |
| 数据 | 内存列表，重启即恢复初始 | 数据库持久化 + 备份 |
| 权限 | 三级硬编码 | RBAC 可配置 + 操作审计 |

**安全提醒**：这是演示门禁，不是真鉴权。工作平台一旦对公网开放，必须先把上表右列做完。
