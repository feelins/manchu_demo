## 4. 移植方案

### 4.1 分工

| 产出 | 做法 | 理由 |
|---|---|---|
| `modules/translate/__init__.py` | 新建：页面路由 + 代理 | 抹平两套协议、隐藏端口、统一错误 |
| `templates/translate/index.html` | 继承 `base.html`，重写布局 | 接入门户统一外壳 |
| `static/css/translate.css` | 完全重制（令牌化） | 源深色主题与门户不一致 |
| `static/js/translate.js` | **重写**（非原样搬运） | 源 JS 直连 localhost 且内含协议分支，重写后前端更薄 |
| `static/js/manju-rules.js` | **新建（公共）** | 消除规则表的第二份拷贝，见 4.3 |

### 4.2 为什么必须代理而不是让浏览器直连

1. **跨机**：门户对外服务时，浏览器所在机器不一定是跑模型的机器，`localhost` 会失效
2. **协议不统一**：8005 是 OpenAI 兼容接口，若放前端，页面要同时维护两套请求/解析逻辑
3. **安全与错误**：不暴露上游端口与堆栈；超时、非 JSON、不可达统一处理

### 4.3 规则表消除重复（本次顺带的重构）

translation 页中间栏与 translit 模块的「拉丁 → 传统满文」是同一套规则。再拷一份必然漂移，因此抽出 `static/js/manju-rules.js` 作为**全站唯一权威来源**：

- `translit.js`：删除内联的 57 行规则定义，改为引用 `window.ManjuRules`
- `translate.js`：同样引用，**不含任何规则常量**
- 回归验证：Node 实跑 `manju-rules.js`，`docs/samples/translit` 的 8 个样例逐字节一致（见 6.3）

### 4.4 文件清单

| 文件 | 说明 |
|---|---|
| `modules/translate/__init__.py` | 蓝图 `/translate/` + `/api/translate/{translate,health}` |
| `templates/translate/index.html` | 页面模板 |

| `static/js/translate.js` | 业务逻辑（走代理） |
| `static/js/manju-rules.js` | **公共规则表**（新） |

`config.py` 仍未改动——`NAV_ITEMS`、`CAPABILITY_CARDS`、`FOOTER_LINKS` 早已预留 `translate` 条目，本次只是把占位路由换成真实蓝图。

## 5. 相对源页面的改动

| # | 源页面行为 | 移植后 | 原因 |
|---|---|---|---|
| 1 | 直连 `http://localhost:800x` | 走相对路径 `/api/translate/*`，由门户代理 | 跨机可用；不暴露端口 |
| 2 | 协议分支写在前端 | 分支上移到代理层，前端只发 `{text,direction,model}` | 前端变薄，便于复用同一套接口做批处理/开放 API |
| 3 | 历史记录存 40 字截断，点击回放会把截断文本塞回输入框 | 存全文，列表里才截断显示 | 源页面是缺陷：回放结果不完整 |
| 4 | 复制用 `document.execCommand('copy')` | 优先 `navigator.clipboard`，失败回退 | 与门户其它页面一致；execCommand 已废弃 |
| 5 | 健康轮询 3 秒 | 10 秒 | 源页面对每个模型单独探测，3 秒一次请求过密 |
| 6 | `middleText` 用 `value` setter 劫持驱动刷新 | 显式调用 `updateMiddlePanel()` | 劫持原型 setter 属隐式副作用，难以维护 |
| 7 | 无「服务未就绪」提示 | 三个模型全离线时显示可执行提示条 | 本机当前就是这种状态，必须让用户知道原因 |
| 8 | 深色全屏 + 科技蓝 | 门户白卡片 + 鎏金 | 视觉统一（映射同 OCR / 文字转换两次移植） |

**保持不变**：方向配置、模型清单与命名、prompt 原文、`temperature/max_tokens`、20 条历史上限、字体检测、导出 TXT 格式。
（prompt 措辞对翻译效果敏感，逐字保留。）
